# בדיקות MedTime

## בדיקות סטטיות ובנייה

מתוך שורש הפרויקט:

```bash
npm run typecheck
npm run build
npm run format:check
```

בדיקת הטיפוסים בודקת התאמה ל־TypeScript. הבנייה יוצרת את חבילת הטיפוסים המשותפת, את שרת Node.js ואת לקוח React. `format:check` בודקת עיצוב עקבי עם Prettier; `npm run format` מתקנת את העיצוב בקבצי הפרויקט. בדיקות אלה אינן מוכיחות שתהליכי המשתמש עובדים מול MongoDB.

## בדיקות אינטגרציה

הבדיקות צריכות לרוץ מול מסד MongoDB ייעודי לבדיקות, באמצעות `TEST_MONGODB_URI`. אין להפנות כתובת זו למסד ייצור או למסד עם נתונים שברצונכם לשמור.

```bash
TEST_MONGODB_URI='mongodb://127.0.0.1:27017/medtime_test?replicaSet=rs0' npm test
```

נדרשת תוצאה עם מספר בדיקות שבוצעו. ריצה ללא בדיקות או suite שדולג עקב MongoDB חסר אינה הוכחת תקינות.

בקובץ `server/tests/integration.test.ts` קיימות 14 בדיקות אינטגרציה. הן מכסות hash ועוגיות התחברות, התאמת תפקיד לחשבון, הרשאות, קלט זדוני, מגבלת הסיסמה של bcrypt ב־UTF-8, רשימת רופאים, חישוב זמינות, התמדה, בקשות הזמנה מקבילות, בעלות וביטול, הזמנה מנהלית, שינוי שעות סותר, תחרות בין הזמנה לשינוי שעות, היסטוריה וסיום ביקור, משוב, השבתת משתמש, בדיקת בריאות וחסימת שינוי ממקור זר. כמה תרחישים נבדקים באותה בדיקה.

בקובץ `server/tests/scheduling.test.ts` קיימות שתי בדיקות יחידה נוספות למנוע הזמנים: התאמה לתאריך המקומי בישראל בעונות שעון קיץ וחורף, וכיבוד הפסקות, ימים ללא קבלה וחלון סיום שאינו מספיק לתור מלא. `npm test` מפעילה את שני הקבצים — 16 בדיקות בסך הכול.

בדיקת התחרות שולחת שש בקשות מקבילות לאותו חלון ובודקת הצלחה יחידה וספירת רשומות פעילה במסד. היא אינה בדיקת עומסים רחבה, אינה מדמה השבתת שרת ואינה מוכיחה התאוששות מכל כשל רשת.

MongoDB לבדיקות צריך להיות replica set, כמו שרת הפיתוח. תהליך CI בקובץ `.github/workflows/ci.yml` מכין MongoDB ומריץ בדיקת טיפוסים, בנייה ובדיקות שרת. לפני השימוש בכתובת מסד בדיקות, ה־suite מוודא ששמו מסתיים ב־`_test`, משום שהוא מנקה את האוספים בין בדיקות.

## בדיקות דפדפן אוטומטיות

בדיקות Playwright בקובץ `e2e/clinic.spec.ts` דורשות שרת ולקוח פועלים, MongoDB וחשבונות הדגמה. מתוך שורש הפרויקט, במסוף הראשון:

```bash
bash scripts/start-db.sh
npm run seed
npm run dev
```

השאירו את התהליך פעיל, ובמסוף נוסף הריצו:

```bash
npm run test:e2e
```

נדרשת התקנת Chromium. בסביבת הענן הוא נמצא ב־`/usr/bin/chromium`; ניתן לבחור נתיב אחר באמצעות `CHROMIUM_PATH`. במחשב שבו אין Chromium מערכתי, אפשר להתקין את גרסת Playwright באמצעות `npx playwright install chromium` ולהשתמש בברירת המחדל של Playwright בהתאם להגדרה. בסיס הבדיקה הוא `http://localhost:5173`, בהתאמה ל־`CLIENT_ORIGIN` של הפיתוח. אין לשנות ל־`127.0.0.1` בלי להתאים את שני הערכים.

חמשת תרחישי הדפדפן מכסים הרשמה, הזמנה ורענון זמינות חי, ביטול ומשוב; כניסת רופא ויומן יומי ושבועי; כניסת מנהל ומסכי ניהול; תצוגה ציבורית במובייל והגנה על מסכים פרטיים; והתאמת כל שלושת אזורי התפקידים למסך נייד. הבדיקות יוצרות נתוני בדיקה בסביבת ההדגמה — אין להריץ אותן על נתוני אמת. במקרה כשל נשמר trace תחת `test-results/`, המוחרג מ־Git.

## מצב האימות בהרצת הפיתוח

| בדיקה                                | תוצאה שנצפתה                                           |

תוצאות אלה מתארות את סביבת הפיתוח שנבדקה, ואינן טענה שהמערכת נבדקה בפריסה אחרת או בעומס ייצור.

## בדיקה ידנית בדפדפן

1. הפעילו MongoDB, טענו נתוני הדגמה והפעילו `npm run dev`.
2. בדקו חיפוש רופא ובחירת תאריך כאורח; ניסיון הזמנה צריך לדרוש התחברות.
3. התחברו כמטופל, הזמינו תור, בדקו שהוא מופיע באזור האישי ובטלו אותו.
4. התחברו כרופא ובדקו יומן, פרטי ביקור והרשאות היסטוריה.
5. התחברו כמנהל, צרו רופא ומטופל, עדכנו קבלה והזמינו תור בשם מטופל.
6. שלחו משוב מחשבון מחובר ובדקו את קבלתו באזור המנהל.
7. פתחו שני חלונות כדי לבדוק רענון זמינות; בדיקת התחרות האוטומטית היא הבדיקה המחייבת למניעת כפל הזמנות.

תוכנית זו מגדירה את הבדיקות הנדרשות. בדיקות שהורצו בפועל ותוצאותיהן מדווחות בנפרד בעת מסירת הפרויקט.
