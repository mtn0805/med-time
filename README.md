# MedTime

מערכת לניהול מרפאה, משתמשים ותורים, לפי הצעת הפרויקט. ממשק בעברית מימין לשמאל; React ו־MUI בלקוח, Express ו־TypeScript בשרת, ו־MongoDB עם Mongoose לשמירת המידע.

## יכולות

- אורחים: עיון ברופאים ובהתמחויות, חיפוש ובדיקת זמינות.
- מטופלים: הרשמה והתחברות, קביעת תור, צפייה בתורים, ביטול תור עתידי ועדכון פרטים אישיים.
- רופאים: יומן יומי ושבועי, צפייה בפרטי תור ובהיסטוריית ביקורים מורשית, עדכון סטטוס והזנת סיכום ביקור.
- מנהלי מרפאה: ניהול משתמשים ורופאים, שעות קבלה ואורך תור, יצירת מטופלים, קביעת תור ידנית וקריאת משוב.
- עדכוני זמינות דרך SSE; השרת בודק שוב את הזמינות בכל הזמנה. הנתונים נשמרים ב־MongoDB.

## התקנה מקומית

דרושים Node.js בגרסה 22.12 ומעלה, npm ו־Docker עם Compose. קובץ `.nvmrc` בוחר Node.js 24. פעולות היומן משתמשות ב־MongoDB transactions, ולכן נדרש replica set. ניתן להשתמש במקום Docker בשרת MongoDB מתאים או ב־Atlas ולעדכן את `MONGODB_URI`; שרת MongoDB עצמאי ללא replica set אינו מספיק.

מתוך שורש הפרויקט:

```bash
npm ci
node scripts/setup-env.mjs
bash scripts/start-db.sh
npm run seed
npm run dev
```

סקריפט ההכנה יוצר `server/.env` עם מפתח `JWT_SECRET` אקראי אם הקובץ אינו קיים, ושומר קובץ קיים ללא שינוי. קובץ זה מוחרג מ־Git. אם מכינים תצורה ידנית, יש להחליף את ערך הדוגמה במפתח אקראי של 32 תווים לפחות.

`scripts/start-db.sh` מפעיל את שירות MongoDB שב־Compose, מאתחל את `rs0` אם נדרש וממתין ל־primary זמין. הנתונים נשמרים ב־volume בשם `medtime-mongo`. ניתן להריץ את הסקריפט שוב עם volume קיים. MongoDB נחשף לפיתוח על כתובת loopback בלבד בפורט 27017. עצירתו באמצעות `docker compose stop mongo` שומרת את הנתונים.

לקוח הפיתוח פועל בפורט 5173 ומעביר בקשות `/api` לשרת בפורט 4000. הלקוח והשרת מופעלים יחד באמצעות `npm run dev`. זמן המרפאה הוא `Asia/Jerusalem`, לרבות מעבר לשעון קיץ. אורך תור ברירת המחדל הוא 20 דקות, וניתן לשנותו בניהול הרופאים.

השרת טוען את `server/.env` לפי מיקומו בקבצים, ולא את `.env` בשורש הפרויקט. משתנים שכבר קיימים בתהליך קודמים לערכים שבקובץ.

| משתנה           | תפקיד                                                                           |
| --------------- | ------------------------------------------------------------------------------- |
| `NODE_ENV`      | `development`, `test` או `production`                                           |
| `PORT`          | פורט השרת; ברירת המחדל 4000                                                     |
| `MONGODB_URI`   | כתובת מסד MongoDB התומך ב־transactions                                          |
| `JWT_SECRET`    | מפתח התחברות אקראי, לפחות 32 תווים                                              |
| `CLIENT_ORIGIN` | מקור הדפדפן המורשה, כולל פרוטוקול ופורט אם נדרש; בפיתוח `http://localhost:5173` |

יש לפתוח את לקוח הפיתוח מאותו מקור שהוגדר ב־`CLIENT_ORIGIN`; מעבר בין `localhost` ל־`127.0.0.1` משנה את המקור. השרת דוחה בקשות שינוי שמגיעות ממקור אחר.

`npm run seed` מיועד לנתוני הדגמה בלבד. אין להשתמש במידע רפואי אמיתי לצורכי הדגמה ובדיקות.

### חשבונות הדגמה

לאחר `npm run seed`, הסיסמה לכל חשבונות ההדגמה היא `MedTime2026!`:

| תפקיד לבחירה בהתחברות | דוא״ל                   |
| --------------------- | ----------------------- |
| מנהל מרפאה            | `admin@medtime.local`   |
| מטופל                 | `patient@medtime.local` |
| רופא — רפואת משפחה    | `doctor@medtime.local`  |
| רופא — רפואת ילדים    | `itay@medtime.local`    |
| רופא — רפואת עור      | `michal@medtime.local`  |

הטעינה שומרת חשבונות קיימים ואינה מאפסת את סיסמתם. אם שיניתם חשבון קיים, השתמשו בפרטים המעודכנים שלו. ה־seed מסרב לפעול כאשר `NODE_ENV=production`, ואינו מופעל אוטומטית בזמן עליית השרת.

## בנייה ובדיקות

```bash
npm run typecheck
npm run build
npm test
npm run format:check
```

בדיקות האינטגרציה דורשות MongoDB זמין ומסד בדיקה נפרד. פרטי ההרצה המדויקים מפורטים ב־[תוכנית הבדיקות](docs/TESTING.md). תוצאות בדיקות מתארות את ההרצה שבוצעה; התיעוד אינו מחליף בדיקת סביבת יעד.

`npm test` מפעילה 14 בדיקות אינטגרציה מול MongoDB ושתי בדיקות יחידה למנוע הזמנים. לבדיקות דפדפן יש להשאיר את `npm run dev` פעילה לאחר טעינת נתוני הדגמה ולהריץ במסוף נוסף `npm run test:e2e`. דרישות Chromium ופירוט ארבעת התרחישים נמצאים במסמך הבדיקות.

הפרויקט משתמש ב־Prettier לעיצוב קוד עקבי. `npm run format:check` בודקת את הפורמט, ו־`npm run format` מעדכנת אותו.

לאחר בנייה, `npm start` מפעיל את השרת המהודר. הגדרת סביבת ייצור, מפתח התחברות ומסד נתונים מתאימים נדרשת לפני חשיפה לרשת.

## מבנה הפרויקט

```text
client/           React, MUI, מסכים וקומפוננטות משותפות
server/           REST API, הרשאות, לוגיקה עסקית וגישה למסד
packages/shared/  טיפוסים וחוזים המשותפים ללקוח ולשרת
docs/             ארכיטקטורה, מיפוי דרישות, חוזה API ובדיקות
```

השרת בנוי בשכבות ובמחלקות נפרדות לפי תחום: חמישה בקרים עבור התחברות, רופאים, תורים, ניהול ומשוב; חמישה repositories עבור משתמשים, רופאים, זמינות, תורים ומשוב; ושירותים ייעודיים לכללים העסקיים. כל בקר ומאגר נמצאים בקובץ נפרד. דפוסי Repository, הזרקת תלויות דרך בנאים ו־Observer משמשים להפרדת תחומי אחריות ולבדיקת הלוגיקה. פירוט המחלקות, חיבור התלויות והתרשימים נמצאים ב־[מסמך הארכיטקטורה](docs/ARCHITECTURE.md).
